Built

I built ML-Ticker as an internal Python command line application for equity research workflows, allowing analysts to retrieve FactSet market data, define custom financial metrics through configuration files, and export formatted reports to terminal tables and styled Excel workbooks.

Hard parts

  • Allowing analysts to write custom formulas required building a restricted syntax tree evaluator that safely prevented arbitrary code execution while supporting mathematical expressions.
  • Formulas frequently depended on other calculated metrics, requiring an internal dependency graph to resolve evaluation order and detect circular references before querying external APIs.
  • Financial queries often returned incomplete data points that needed typed missing-value representations to keep calculated workbook columns from failing silently.
  • Managing differences between point-in-time portfolio holdings and historical time-series queries required separate data models and multi-stage retrieval pipelines.

Learned

Building internal research tools requires validating user configurations and mathematical expressions up front so errors are caught before making expensive data queries.

Also

  • Command line interface with subcommands for snapshot queries, time-series data, metric validation, and peer valuation comparisons.
  • Safe expression parser that validates custom metric formulas using abstract syntax tree inspection.
  • Dependency resolution algorithm that evaluates interdependent metrics in topological order without heavy external graph libraries.
  • Report generation with formatted terminal display and multi-tab Excel workbooks containing hidden calculation sheets.

Project context and overview

During my summer internship with Merrill Lynch Wealth Management, I worked on software supporting an internal calculations platform used for portfolios managing more than $500M in assets. Analysts frequently needed to pull fundamental data and historical pricing from FactSet, apply team-specific valuation formulas, and generate clean reports for review. Because this was proprietary internal software, the source code is private, but the architectural design provides a good example of how to build reliable data processing tools.

I built ML-Ticker as a packaged Python command line utility running within FactSet's programmatic environment. The tool reads configuration files written in YAML, checks that all requested metrics and custom formulas are valid, batches remote API queries efficiently, and exports the final calculations into colored terminal tables and multi-sheet Excel workbooks.

Safe formula parsing and dependency resolution

One of the central requirements was giving analysts the flexibility to write custom mathematical formulas without opening security vulnerabilities through unsafe Python evaluation. To solve this, I wrote a custom expression validator using Python's abstract syntax tree module. The parser inspects every formula against an allowlist of approved mathematical operators and built-in functions, rejecting attribute lookups, imports, or arbitrary code before anything executes.

Because formulas often build on top of other calculated figures, the application treats the entire metric set as a directed acyclic graph. Before any data is requested from FactSet, the engine computes the topological sort order for evaluation, checks for circular references, and suggests corrections if an analyst misspelled a metric name. This ensures that expensive network requests are never made for invalid configuration files.

Data consistency and report export

Financial data feeds often contain missing values, partial historical dates, or inconsistent data types across different market sectors. If an API returns an empty field, naively coercing it to zero can distort valuation multiples and create misleading spreadsheet results. ML-Ticker treats missing values as explicit typed placeholders throughout the calculation pipeline, ensuring that division by zero or absent data points propagate clearly into the final report.

Once all metrics are computed, the tool formats output depending on the analyst's workflow. Quick lookups display clean terminal tables using the Rich library, while in-depth reviews export styled Excel workbooks with separate sheets for raw data, intermediate calculations, and final presentation summaries, saving the team hours of manual spreadsheet formatting each week.
